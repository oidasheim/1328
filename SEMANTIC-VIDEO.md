# Semantic OpenCLIP + DuckDB workflow

This module indexes a representative middle frame from each video using the
OpenCLIP ViT-B-32 image encoder, stores normalized 512-D vectors in DuckDB, and
selects beat-aligned shots with text/image cosine similarity. It avoids deleting
an existing index and supports CPU inference; CUDA is used only when available.

Install optional dependencies (choose a PyTorch build suitable for your host):

```bash
python -m pip install -e '.[semantic]'
```

Index video clips recursively:

```bash
synapse-index-clips ./CleanClips --db ./database/clips_semantic.duckdb
```

Generate a plan first, then render when ready:

```bash
synapse-semantic-render ./track.mp3 --db ./database/clips_semantic.duckdb --plan-only
synapse-semantic-render ./track.mp3 --db ./database/clips_semantic.duckdb --aspect 9:16 --output ./output/track.mp4
```

The planner dynamically selects restrained cinematic prompts from per-beat audio
energy, retrieves similar clips from DuckDB, and avoids the last three choices
where alternatives exist. FFmpeg uses the track's audio only, strips metadata
and chapters, and prefers NVENC when available, otherwise libx264.

This is a deterministic editing aid, not a predictor of virality or listener
biology. Review media licenses and generated timelines before publication. Rapid
flashing/strobe effects are intentionally not generated by these defaults.

Tests that do not require model weights or GPU:

```bash
pytest tests/test_semantic.py -q
```
